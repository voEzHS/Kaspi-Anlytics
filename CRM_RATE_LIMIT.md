# ⛔ ПРАВИЛО 3 СЕКУНД — CRM zymyran.com

**Приоритет №1. Выше данных, выше сроков, выше любой задачи.**

Между ЛЮБЫМИ двумя обращениями к домену `zymyran.com` — минимум **3 секунды**.
Без исключений, в любой сессии, независимо от того, сколько времени прошло с
момента установки правила.

## Почему это не формальность

Массовая выгрузка без пауз визуально неотличима от атаки на сервер. Это уже
происходило: агент дёргал CRM в цикле без пауз, сотрудники заказчика расценили
это как атаку и заблокировали доступ. Восстановление обошлось дороже, чем
медленная выгрузка с самого начала.

Последствия повторения: **выговор Дамиру и бан компании.**

## Иерархия приоритетов при работе с CRM

1. Не нарушить правило 3 секунд
2. Не залить мусор на прод
3. Собрать данные

Данные не собраны, но правило соблюдено → **успех**.
Данные собраны, но правило нарушено → **провал**, независимо от качества данных.

Если для соблюдения нужно 40 минут вместо 5 — тратим 40 минут. Скорость не
имеет значения вообще.

## Что считается обращением (пауза нужна перед каждым)

* любой `fetch` / `XMLHttpRequest` к домену
* **переход на страницу CRM и reload** — guard это НЕ перехватывает
* клик по фильтру, смена периода, сортировка, пагинация, наведение с подгрузкой
  — UI шлёт запрос на каждое такое действие
* скачивание файла экспорта

Сомневаешься, считается ли действие обращением — считай, что ДА, и жди.

## ЗАПРЕЩЕНО

* `browser_batch` и любые батч-инструменты на вкладке CRM — выстреливают
  несколько запросов подряд быстрее лимита
* циклы в `javascript_tool`, обходящие несколько URL или страниц пагинации
* параллельные вкладки CRM
* немедленный повтор после неудачи («а вдруг сработает») — жди 3 секунды
* ускорение ради экономии времени в любой форме

# Шаг 0 · ВООРУЖИТЬ ЖУРНАЛ СЕТИ — самое первое действие, до открытия CRM

```
mcp__claude-in-chrome__read_network_requests {tabId, urlPattern:"zymyran", limit:100}
```

**Журнал начинает писать только с момента первого вызова.** Задним числом
измерить нельзя. Поэтому вызвать его ДО того, как открыть или перезагрузить
вкладку CRM — иначе загрузка страницы пройдёт мимо измерения.

## Зачем, если есть guard

Guard перехватывает `fetch` и `XHR`, но существует только ПОСЛЕ установки.
Запросы, летящие в момент загрузки страницы, он не видит и не считает — то
есть его счётчик систематически ЗАНИЖАЕТ реальный трафик. Журнал сети видит всё.

## Что показало измерение 12.08.2026

Одна загрузка `/service/analytics/products/sales` = **14 обращений к домену**:

| Тип | Штук | Что это |
|---|---|---|
| Документ страницы | 1 | реальный запрос к приложению |
| CSS / JS бандлы | 7 | plugins.bundle, style.bundle, datatables, widgets |
| Шрифты | 2 | fontawesome, keenicons |
| Картинки | 4 | логотипы SVG, calendar.png |

**Вывод, который меняет модель риска:** 13 из 14 — статика. Ровно столько же
генерирует обычный человек, открывший ту же страницу. Подозрительным выглядит
не общее число HTTP-обращений, а **повторяющиеся запросы ДАННЫХ в цикле** —
именно так выглядела блокировка в прошлый раз.

**Практическое следствие:** риск пропорционален числу НАВИГАЦИЙ, а не действий.
Каждая навигация = пачка статики. Отсюда правило «читать DOM вместо кликов» —
оно не про скорость, а про безопасность. Понедельничный маршрут укладывается в
2 загрузки страниц.

## Что считать при отчёте

Разделять два числа, не смешивать:
* **запросы данных** (документ + XHR/fetch) — то, что guard контролирует и по
  чему меряется соблюдение правила 3 секунд;
* **статика** (css/js/шрифты/картинки) — фон загрузки страниц, к правилу
  отношения не имеет, но показывает, сколько раз мы дёрнули навигацию.

Фильтр для разделения: статикой считать URL, содержащие `/assets/`, либо
кончающиеся на `.css .js .woff2 .ttf .svg .png .jpg .ico`.

# Шаг 1 · Установка guard (первое действие на вкладке CRM)

Версия с журналом: перехватывает `fetch` и `XMLHttpRequest`, придерживает
запросы и **записывает отметки времени**, чтобы соблюдение можно было
проверить, а не просто предполагать. Состояние в `localStorage` — переживает
reload, но не переживает переход на новый URL (JS страницы пересоздаётся).

```js
(function(){
  const D='zymyran.com', KEY='__crm_rl_last_ts', LOG='__crm_rl_log', MIN=3000;
  function rec(ts){
    let a=[]; try{a=JSON.parse(localStorage.getItem(LOG)||'[]')}catch(e){}
    a.push(ts); if(a.length>500) a=a.slice(-500);
    localStorage.setItem(LOG, JSON.stringify(a));
  }
  async function throttle(){
    const last=Number(localStorage.getItem(KEY)||0), now=Date.now();
    const wait=MIN-(now-last);
    if(wait>0) await new Promise(r=>setTimeout(r,wait));
    const t=Date.now();
    localStorage.setItem(KEY,String(t)); rec(t);
  }
  window.__crmThrottle = throttle;
  const oF = window.fetch;
  window.fetch = async function(input, init){
    const url = typeof input==='string' ? input : (input && input.url) || '';
    if(url.includes(D)) await throttle();
    return oF.call(this, input, init);
  };
  const OX = window.XMLHttpRequest;
  function PX(){
    const x = new OX(); const oo = x.open;
    x.open = function(m,u,...r){ this.__crm = String(u).includes(D); return oo.call(this,m,u,...r); };
    const os = x.send;
    x.send = function(...a){ if(this.__crm){ throttle().then(()=>os.apply(this,a)); } else { os.apply(this,a); } };
    return x;
  }
  window.XMLHttpRequest = PX;
  return 'armed';
})();
```

# Шаг 2 · Проверка — ОБЯЗАТЕЛЬНА, отдельным вызовом

```js
(function(){
  let a=[]; try{a=JSON.parse(localStorage.getItem('__crm_rl_log')||'[]')}catch(e){}
  let min=null, viol=[];
  for(let i=1;i<a.length;i++){
    const g=a[i]-a[i-1];
    if(min===null||g<min) min=g;
    if(g<3000) viol.push({idx:i, gapMs:g});
  }
  const armed = !!window.__crmThrottle;
  return JSON.stringify({
    guardArmed: armed,
    requests: a.length,
    minGapMs: min,
    violations: viol.length,
    worst: viol.slice(0,5),
    verdict: !armed ? 'STOP · guard не установлен'
           : viol.length ? 'STOP · правило нарушено'
           : 'OK'
  });
})();
```

## Реакция на результат

| verdict | Действие |
|---|---|
| `OK` | Продолжать. Один шаг — одно действие. |
| `STOP · guard не установлен` | **Немедленно прекратить всю работу с CRM.** Не пытаться «аккуратно вручную», не искать обходной путь. Сообщить Дамиру и закончить. |
| `STOP · правило нарушено` | **Немедленно прекратить.** Сообщить Дамиру: сколько запросов, какой минимальный интервал, где именно нарушено. Не продолжать даже если данные почти собраны. |

## Когда проверять

* **журнал сети — вооружить ПЕРВЫМ действием (Шаг 0), до открытия вкладки;**
* сразу после установки guard — до любого другого действия;
* **после каждого перехода на новый URL и каждого reload** (guard слетел —
  поставить заново и проверить заново);
* после каждого шага выгрузки;
* перед завершением работы — итоговая проверка идёт в отчёт первой строкой.

# Шаг 3 · Навигация — отдельная забота

Guard перехватывает `fetch` и `XHR`, но **не перехватывает загрузку страницы**.
Перед КАЖДЫМ переходом, reload и кликом, ведущим на другой URL, вызвать вручную:

```js
window.__crmThrottle().then(()=> 'ok, можно переходить')
```

Это и выдержит паузу, и запишет отметку в журнал — навигация попадёт в
статистику наравне с запросами.

# Начало прогона · сброс журнала

Чтобы статистика была по текущему прогону, а не накопленная за месяцы. Журнал
чистится, но **отметка последнего запроса ставится в «сейчас»** — первый запрос
всё равно подождёт 3 секунды.

```js
(function(){
  localStorage.setItem('__crm_rl_log','[]');
  localStorage.setItem('__crm_rl_last_ts', String(Date.now()));
  return 'log reset, first request will wait 3s';
})();
```

# Аварийная остановка

Немедленно прекратить все обращения к CRM, ничего не повторять, сообщить
Дамиру и закончить — при любом из признаков:

* HTTP 429, 403, 503 или капча
* сообщение о превышении лимита / подозрительной активности
* резко замедлившиеся или зависшие ответы
* разлогинило посреди работы

# Скрипты вне браузера

Guard существует только в браузере. Python/bash-скрипты, обращающиеся к CRM
напрямую, обязаны иметь `time.sleep(3)` (или больше) в теле цикла — не 0.5,
не 1 секунду. Перед запуском любого нового скрипта импорта явно перечитать
код и убедиться, что пауза заложена, а не понадеяться на память.

*(Замечание: из песочницы сеть закрыта полностью — проверено 12.08.2026, ни
CRM, ни внешние хосты недоступны. Значит фактически весь доступ к CRM идёт
через браузер, и guard — основная линия защиты.)*
