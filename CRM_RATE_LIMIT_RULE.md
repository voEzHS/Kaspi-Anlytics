# Правило 3 секунд при выгрузке из CRM — инструкция для агента

Самодостаточный файл, не зависит от TorgStore. Можно копировать в любой другой проект как CLAUDE.md / project instructions или просто как загруженный документ в контекст.

## Зачем это правило

Массовая выгрузка данных из CRM в цикле без паузы (несколько запросов в секунду) визуально неотличима от атаки на сервер. В одном из проектов ровно это и произошло: агент дёргал CRM без пауз при массовом импорте, сотрудники заказчика расценили это как атаку и заблокировали доступ. Восстановление доступа обошлось дороже, чем медленная, но безопасная выгрузка с самого начала.

Отсюда правило: **скорость выгрузки не важна, важно не попасть под блокировку.**

## Само правило

Между ЛЮБЫМИ двумя запросами к домену CRM (любой эндпоинт — списки, детали лида/сделки, аналитика, фильтры и т.д.) должно проходить **минимум 3 секунды**. Без исключений, независимо от того, сколько времени прошло с момента установки этого правила и в какой сессии/разговоре находится агент.

Практически это значит:

- Любой bash/python-скрипт, который в цикле обращается к CRM (импорт по сущностям × периодам и т.п.), обязан делать `time.sleep(3)` (или больше) между итерациями — не 0.5, не 1 секунду, а минимум 3.
- Любая последовательность действий в браузере (клики по фильтрам, смена периода, наведение, вызывающее AJAX-запрос на каждое действие) тоже должна быть разнесена минимум на 3 секунды между сетевыми запросами к CRM, а не только между UI-действиями.
- Если нужно выгрузить много данных (по многим сущностям/периодам) — это нормально, что это займёт минуты, а не секунды.
- Перед любым новым скриптом импорта — явно перепроверить, что пауза заложена в код, а не полагаться на память/намерение.
- Если неясно, считается ли конкретное действие «запросом к CRM» — по умолчанию трактовать в пользу осторожности и добавлять паузу.

## Технический guard — не полагаться только на память агента

Текстовое правило выше — это то, что агент обязан ПОМНИТЬ. Чтобы не зависеть от памяти (в т.ч. в новой сессии, у другого агента, после сжатия контекста), используется JS-снипет, который технически ГАРАНТИРУЕТ ≥3с между запросами к домену CRM — перехватывает `fetch` и `XMLHttpRequest` на странице CRM и придерживает любой запрос к этому домену, пока не пройдёт 3с с прошлого. Состояние хранится в `localStorage`, поэтому переживает reload вкладки (но не переживает переход на новый URL внутри домена CRM — там JS страницы полностью пересоздаётся).

```js
// CRM rate-limit guard — переживает reload (localStorage, а не память вкладки).
// Перехватывает fetch И XMLHttpRequest — то есть работает и для ручных fetch,
// и для запросов, которые сам UI шлёт при клике/наведении/смене фильтра.
//
(function(){
  const CRM_DOMAIN = 'zymyran.com';
  const KEY='__crm_rl_last_ts', MIN_GAP=3000;
  async function throttle(){
    const last=Number(localStorage.getItem(KEY)||0), now=Date.now();
    const wait=MIN_GAP-(now-last);
    if(wait>0) await new Promise(r=>setTimeout(r,wait));
    localStorage.setItem(KEY,String(Date.now()));
  }
  window.__crmThrottle = throttle;
  const origFetch = window.fetch;
  window.fetch = async function(input, init){
    const url = typeof input==='string' ? input : (input && input.url) || '';
    if(url.includes(CRM_DOMAIN)) await throttle();
    return origFetch.call(this, input, init);
  };
  const OrigXHR = window.XMLHttpRequest;
  function PatchedXHR(){
    const xhr = new OrigXHR();
    const origOpen = xhr.open;
    xhr.open = function(method, url, ...rest){
      this.__isCrm = String(url).includes(CRM_DOMAIN);
      return origOpen.call(this, method, url, ...rest);
    };
    const origSend = xhr.send;
    xhr.send = function(...args){
      if(this.__isCrm){ throttle().then(()=>origSend.apply(this,args)); }
      else { origSend.apply(this,args); }
    };
    return xhr;
  }
  window.XMLHttpRequest = PatchedXHR;
  console.log('%c[CRM rate-limit guard armed] минимум 3с между запросами к CRM, живёт до reload/навигации', 'color:#0a0;font-weight:bold');
})();
```

## Обязательный порядок действий при работе с вкладкой CRM в браузере

Это касается и работы через консоль вручную, и через браузерную автоматизацию (например, Claude in Chrome / `javascript_tool`):

1. Открыть/перейти на вкладку CRM.
2. ПЕРВЫМ ДЕЙСТВИЕМ выполнить guard-снипет выше (например через `javascript_exec`).
3. Только после этого — любые клики, навигация внутри домена CRM, ручные `fetch`-запросы к CRM.
4. Если случился reload или переход на новый URL внутри домена CRM — guard слетает (JS-состояние вкладки сбрасывается), значит перед следующим действием вставить его заново (шаг 2).

Guard не отменяет `time.sleep(3)` в python/bash-скриптах, которые обращаются к CRM напрямую (не через браузер) — для них технического перехвата нет, там пауза зашивается в сам скрипт.

## Быстрая проверка, что guard стоит и не сработает случайно рано

```js
JSON.stringify({
  guardArmed: !!window.__crmThrottle,
  lastRequestTs: localStorage.getItem('__crm_rl_last_ts'),
  now: Date.now()
});
```
