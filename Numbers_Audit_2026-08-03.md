## Найдено 2 реальных бага

### 1. `/api/v1/analytics/months` падал с 500 для Холод.витрин

Причина: `_month_sort_key()` в `analytics.py` парсил год из месяца через `int(parts[1])` без защиты. В базе остались "сырые" строки вроде `"Июнь 15'"` (сама аналитика их уже не учитывает благодаря Rule 3, но физически строки в БД не удалялись) — `int("15'")` падает с `ValueError`, весь эндпоинт отдавал 500.

**Исправлено**: обёрнул в try/except (год по умолчанию 0 вместо краша) и добавил ту же фильтрацию контаминированных значений, что уже стоит в /subtypes — грязные месяцы больше не будут предлагаться как опция в фильтре.

### 2. Название товара = код товара (старый баг #54, подтверждён и локализован)

В Морозильниках **664 из 816 строк (81%)** показывают код вместо названия на вкладках Товары/ABC/Приоритеты. Остальные 3 отдела — чисто (0 плохих строк).

Причина найдена точно: это старый баг маппинга колонок при загрузке (уже пофикшен для новых загрузок), но для товаров, загруженных ДО фикса, поле name в базе уже сохранено как копия kod. При этом для многих из этих SKU есть и другие месяцы, где имя записано верно (пример: код 135246793 — в строке "Июнь 2026" имя "Friggier J SD365BY 365 л серый", а в строке "Май" — просто "135246793"). Функция dedup_skus() берёт первую попавшуюся строку и не проверяет, есть ли для того же кода более удачная запись.

**Исправлено**: добавил `/uploads/self-heal-names` — лечит название прямо из уже загруженных данных отдела (без пересылки файла заново), находит для каждого кода лучшее известное имя и патчит битые строки. Гарантированно закрывает все коды, для которых хоть где-то есть нормальное имя.

## Второстепенное (не критично, на заметку)

- В Морозильниках список типов приходит в разном регистре: `["Ларь","бонета","шкаф","шок"]` — смешение заглавных/строчных, чисто косметика.
- Формат месяца плавает: где-то "Июнь 2026", где-то просто "Июнь" — сортировка это переживает (год есть в ключе сортировки), но выглядит непоследовательно на глаз.
